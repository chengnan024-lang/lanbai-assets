## v4（门 round 3，2026-10-01）改了什么——**先读这一节**（下面的 v3 一节仍然描述数据契约）

门的 round-2 评审（`gate/critique_awe_r2.md` B4、`gate/critique_tech_r2.md` M2 / M4 / minor）：v3 读起来是“一块放在石头里的水晶”，
三层同心的内唇 + 两侧肉色的褶有**解剖学的读法**，四片翻布像锡纸 / 紫晶块，上端像闪电，天空本身没有被拉扯。v4 的改法：

1. **没有嵌套的内唇。** 白里的纵深只来自：圣经的明度衰减（40% 高处 100% → 两端 70%，无条纹）；右缘一条**布的厚度**
   （透镜宽度的 6.5%，`#3E3C66 → #5B5A88`，翻布那一段没有）；以及 4 片**形状各不相同**的内层薄纱（斜片、斜片、分叉、垂片），
   各自偏离 6–15%、倾斜 12–24°，从不与透镜轮廓同形（`tear_def.VEILS`）。
2. **左缘长而干净，右缘毛糙**（左 2 个小缺口、右 4 个 + 全程的纱头毛边）。
3. **只有两片翻布，薄、焊在唇上**：右边 35–60% H 的“剥开”（铰链 250 m、布宽 135 m、上举 50°、边缘外卷 200°），左边 15–25% H 的小卷
   （铰链 105 m、布宽 80 m）。**外面 = 天空自己的颜色**（`_OuterSky` × LanbaiHorizon / `_HazeColor`，不加光晕：布挡住了光），所以它在天上
   几乎看不见，只在盖住白的地方读成一块深色的布；里面（被伤口照亮，`0.15 + 0.6 R`）只在卷起的唇上露出来；轮廓光只沿卷边 1–2 px、C\* ≤ 20。
   **v4 修正**：v4 草稿的法线符号反了（车看到的全是里面），已改；`tear_def.flap_surface` 的 `n_ana`。
4. **手指抓住布**：`tear_def.GRIPS` 6 个抓点（左卷 2 个 + 左唇 1 个，右剥 3 个），布在抓点处被向车、向外、向下“顶起” 12–26 m（宽的高斯），
   并有一条从抓点进入布面的折。门的两只手（`gate_layout.hand_ctrl`）的指尖就落在这些点上，随张开和 H(t) 一起移动（`grip_cf`）。
5. **上端 16% 是一排“拉链线”**：9 根横跨开口的深色纱线（`#2A2C44`，≥ 0.15° 宽，VR 可见），其中 2 根断了（两头各剩一截下垂的线头）；
   再往上一条**发丝裂**（`Tear_Rip_Hairline`，1–2 px，无辉光，带两根小枝）继续往黑里跑 340 m。
6. **天是布**：`Tear_SkyFolds` v4 不再是烟，而是 17 道弯曲、收尖、向锚点会聚的**张力褶**（上端 6、下端 5、右剥 4、左卷 2），±4–6 L\*，
   都在 1.5 H 以内；采样改密（v4 草稿的稀疏折线在 1:1 下变成虚线）。
7. **分叉裂 = 暗唇的透镜**（6–12 m 宽，路径平滑，不再是闪电），辉光 ≤ 1.5 倍宽。
8. **光晕多一张内卡**（约 0.15 H 半径、增益 2.8 → UV2.x，shader `_PART_HALO` 读它）：唇外 1–3° 的 `#5B57A1` 呼吸（技术评审 M2）。
9. shader v4：Flap 部分按上面改；**深度预通道 × `CloudFootFade`**（云顶以下不写深度，技术评审 minor）；Halo 每卡增益。
   slang 语法 / 类型检查 8 个部件全部通过（**仍未在 Unity 编译**）。
10. 门里不用套件自己的 12 张光束扇（`Tear_Shafts`），用 `GateLayout_v2.json shafts` 的 2 束（门 FSE 预算，`gate/final/fse_U8.json`）。

重建：`tear/v2/make_textures.py` → `build_kit.py` → `verify_fbx.py`（全部部件位置误差 ≤ 1.2e-4 m，3 套 UV，翻布法线 = 源）。
`Source/` 已同步。`Renders/` 里仍是 v2 的预览图——v4 的样子以门的定稿为准（`gate/final/`，裂口在每一张里）。

## 2. 网格与数据约定

**物体空间（Unity，`Tear_Root` 的本地空间）：** +Y 向上；套件**正面朝 +Z**（车在 +Z 那一侧）；+X 在车上看是**左**（Unity 的 X 镜像），所以材质里的 `_TearAcrossOS`（车上看“向右”）= `(-0.99756, -0.06976, 0)`，`_TearAxisOS`（透镜轴，向上、顶端右倾 4°）= `(-0.06976, 0.99756, 0)`。原点 = 透镜轴与云顶高度的交点。根缩放 1 = 裂口在云顶以上高 **H = 1000 m**、**全开（宽 30% H）**。

**顶点数据（shader 依赖，导入时请：Mesh Compression = Off；Generate Lightmap UVs = 关——它会覆盖 UV2；Normals = Import）：**

| 通道 | 内容 |
|---|---|
| UV0 (`TEXCOORD0`) | 贴图 UV |
| UV1 (`TEXCOORD1`) | x = **a_hinge**：该顶点“挂在哪一点上”的横向偏移（m，全开时）。shader 把顶点沿 `_TearAcrossOS` 移动 `a_hinge × (w − 1)`，w = 当前宽度 / 30%。透镜自己的横坐标就是 a，于是透镜按比例变窄；翻卷布、纤维、分叉裂跟着它们的唇平移；褶皱卡只在两唇之间被压缩。y = 相位（摆动 / 飘动 / 呼吸滞后）。 |
| UV2 (`TEXCOORD2`) | 分叉裂：x/y = `_Udon_RipProgress` 的窗口（A：0–0.75，B：0.25–1）；光束：x = 半宽（m），y = 长度（m）。 |
| COLOR | 翻卷布：R = 内面接到的裂口光，G = 外面接到的裂口光，B = 折线 → 撕边（0–1），A = 飘动权重。光束：RGB = 光束轴（物体空间）× 0.5 + 0.5（法线带不过 FBX/Unity，所以放在颜色里）。 |
| NORMAL | 翻卷布 = 外面的法线（已核对：FBX 里与源数据点积 = 1.0000）。 |

我们已用 Blender 自带的 FBX 解析器（和 Unity 的 FBX SDK 读的是同一份数据）核对过：顶点 = 源数据 (x, z, −y)、误差 ≤ 1e-4 m；每个网格 3 层 UV；翻卷布法线、光束轴颜色逐顶点一致；UpAxis = Y、UnitScale = 100。

## 6. 各部件的美术说明

**透镜（未染的白）。** 核心填 `#FFEDD1 @ +1.84`（屏幕 `#F5F2EC`，×T0 1.68：柔和地晕），**最宽处最亮，向两端淡到 70%**。核心不是平的光：
- 白布本身有沿轴的经纱细纹和很淡的褶；
- **第二层布**（`#DFCFFF @ +1.96` × 0.8，淡紫白）：撕得更窄，而且**斜着错开**：低处挂在左唇、高处挂在右唇，最深的白在它旁边斜着走。它的撕边有一道细暗线（厚度）和细纤维。不同心，不是“透镜里套透镜”（圣经 4c：禁止同心杏仁形）；
- 两唇是**一排撕断的纬纱**（梳齿状、成束，间距 0.9–2.1 m，长 1–16 m），`#DFE6FF @ +1.56`（屏幕 `#E2E8F3`）：朝外的亮纤维压在暗布上，朝里的比核心略冷略暗；
- 窄的两端还有**没断的纬线横跨伤口**（深靛 `#3E3C66` × 1.4，边上一圈透光），宽处有几根断了、从一侧垂下；
- 唇外辉光 `#C6B4FF @ +1.04`（屏幕 `#C0B9E4`，×T0 0.97：不晕），沿纱线方向有条纹，6.5 m + 26 m 两级衰减。

**翻卷的丝绸（×4）。** 每片从唇上的折线开始，先向车的方向竖起、略向伤口内倾（车看到的是**外面**：`#141726` → `#0C0E18`，由折线到撕边），然后向外卷过去（**内面**翻到车这边，接住裂口光 `#3E3C66`；亮度由烘在顶点色里的“朝向伤口”决定），末端卷成一个卷；布上有从折线伸向撕边的拉扯褶和几道垂褶（每片 65–105 m 一褶），卷的棱上有丝绸的光泽（边缘朝向视线时亮）。撕边：两三个撕口、磨穿的小洞、撕边外 1–18 m 的散线；**撕边上 1.5 px 的月光轮廓 `#A9C2FF`**（`fwidth` 保证任何距离都是 1–3 px；强度 0.5 × 填色）。四片大小、翻卷角、扭转、倾斜方向都不同（L1 下垂、R1 上扬……），不对称。

**分叉裂（×2）。** 从伤口上端分出，像布上的应力裂纹：比主伤口暗（看到的白只有核心的 55%，因为有纤维横过），两唇有细纤维和辉光，裂尖永远是尖的。它们沿着天之布顶端的应力扇裂开（见下）。

**天之布的褶皱（新增，美术决定）。** 渲染证明：只有透镜和翻卷布时，它读作“漂在天前面的一个撕破的东西”或“能量裂缝”；加上这张卡，**天本身成了布**，这是圣经那句“天被撕开”的关键。拉开的布会**沿拉力方向起褶**：褶从两唇水平地伸出去（间距不规则，几条主褶 + 许多淡褶，各自在 220–540 m 处消失）；伤口顶端有一把应力扇（两道分叉裂就沿着它走），脚下有一把较弱的扇。褶被裂口光斜照：朝伤口的面加光（`#A99DE1` 方向），背面的谷把后面的天压暗最多 38%。**最外一层紫晕（1500×1750 m）也烘在这张图里**，所以它的 overdraw 等于圣经预算里的第 3 张光晕卡（§8）。不想要时：关掉这个网格，并把 `Halo_512` 复制一张 1500×1750 m 的卡加回 `Tear_Halo`。

**紫晕。** `#8275D0`（屏幕 `#5B57A1`，C\* 45，黄昏靛紫），2 张径向卡 + 褶皱卡里的最外层，呼吸 ±0.25 EV、8 s（外层滞后 0.08 周期，像一口气散开）。实测 U7 时伤口旁的空气读 `#5F618F` 左右。

**光束。** 每张卡 3 束（圣经 2–3），从透镜中下部出发，朝车一侧的天散开（偏航 ±3–18°、俯 8–16°），经过车的上方与两侧（穿过车的只有光带）。深度测试、软淡 40 m、侧视淡出、近处淡入。默认 12 张的扇形只是起点：圣经要它们放在**中层触手之间的缝里**，请用 `Tear_ShaftCard.fbx` 按 `GateLayout.json` 重新摆（砍法：12 → 8 → 6）。

**云海辉光卡。** `#696F8D`（屏幕 `#495270`），半径 1.1 km（× 根缩放），放在云顶高度，软粒子淡出。

## 8. 性能

U8 正前方（俯仰 0）实测 overdraw（全屏等量，FSE）：透镜 0.12，**紫晕 2 张 + 褶皱卡 = 1.00（圣经光晕预算 ≤ 1.0）**，**光束 0.53（≤ 0.7）**，**纤维 0.005（≤ 0.5）**，云海辉光卡 0.47，翻卷布是镂空不透明（不计）。套件合计约 2.1 FSE；加上车厢玻璃 0.7、云海 0.9、远潮 0.2 仍在圣经 4.0 的合计内（辉光卡算在云海里时更宽裕）。U8 抬头（+18°）时：紫晕 0.50 + 褶皱 0.73、光束 0.60。U8 + 7 s（0.48 km）会更大：按圣经 §1.9 的砍法先砍光束（12 → 8 → 6），再把紫晕 2 → 1。

## 9. 与圣经的差异（全部是美术决定，已在渲染里验证）

1. **新增 `Tear_SkyFolds`**（天之布的褶皱），并把第 3 层紫晕烘进去（overdraw 不变）。原因见 §6。
2. 核心里加了**斜着错开的第二层布**（4c 的预告，不同心）。
3. 纤维卡只朝外（叠加的纤维若朝里会把核心加亮）；朝里的纤维画在透镜贴图里（比核心冷、暗）。
4. 分叉裂的白 = 核心的 55%（窄缝里看到的白更少）。
5. 翻卷布的月光轮廓强度 0.5 × `#A9C2FF` 填色、1.5 px：满强度时在暗布上读成霓虹蓝。
6. 月光轮廓用 `fwidth`，保证远近都是 1–3 px。
