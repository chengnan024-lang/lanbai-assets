## 一、曝光：驱动只算，`ApplyGrades` 唯一写（总导演 10-23 的裁决落到接口上）

Director v1 已推（`pkg/engineering` 的 `Director/`，`README_Director.md` §0.5）。你的驱动在 `CONTROL_总控.md` §5 的三个方法之外加**一个可选方法**：

```csharp
public float[] LanbaiGrade(float t)   // {ΔEV, WHITE_SAT 权重, WHITE_BLOOM 权重, 桌面镜头层乘数}；这一帧没有事件 return null
```

- 分发层在你的窗口里、`LanbaiTick(t)` 之后调它，把所有驱动的结果汇总（ΔEV 相加、两个白的权重取大、镜头层乘数取小），本地的 `LB_Journey.ApplyGrades` 读汇总值、和它自己的事件相加，再按圣经 §1.4 的 `w = ΔEV/(4 − b)` 解 EXPO_UP / EXPO_DOWN。**驱动不碰 PPv2 的 volume、不调 `Grading/Runtime/LanbaiExposure`。**
- 所以你的 `ownsExposure = false` 就是唯一的目标模式：`GetDeltaEV()` 等几个 getter 合并成这一个 `LanbaiGrade(t)`。`ownsExposure = true` 的退路可以留着编译，但交付的默认值是 false，README 写明“true 只在没有 Director 的测试场景里用”。
- 遮罩填色的 ΔEV 补偿（`overlay.rgb = 填值 × 2^−ΔEV`）也由写 ΔEV 的那一方做（`LB_Journey`），你只要在 README / JSON 里给出白的遮罩每个时刻的填值和 alpha 曲线。
- `LB_Journey` 现在自己算镜子脉冲（`starCross` 前 9 面）和白的冲击 / 膨胀；你的包合进 main 时，`ApplyGrades` 里这两段要删掉（避免算两遍）——我会写进 `Engineering/README_集成.md` §5 的差异表（第 1、2 条已经在表里：`starCross` 换表、脉冲面数 9 → 11）。
