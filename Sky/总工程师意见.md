## 一、必须改

1. **`LANBAI_FOG_OWN_UNIFORMS` 一个开关藏了三个名字，按文档用一定编译失败**（`LanbaiFog.cginc` 29–42）。
   头注说“自己声明 `_FogCap` / `_FogHeightFalloff` 的 shader 定义这个宏”，但 38–42 行它同时藏掉了 `_Udon_FogDensity`，48 行又要读它 → 未声明（FXC X3004）。你在 `给总控.md` §2 第 2 条给门的做法（TentacleSway 定义宏、把 `_FogCap`、`_Udon_FogDensity` 挪上去）也过不了：TentacleSway 没有 `_FogHeightFalloff`。补充测试 B、E 都复现了。
   **改**：一个名字一个保护，旧宏保留成“三个都自己来”的简写：
   ```hlsl
   #ifdef LANBAI_FOG_OWN_UNIFORMS
     #define LANBAI_FOG_OWN_CAP
     #define LANBAI_FOG_OWN_HEIGHT
     #define LANBAI_FOG_OWN_DENSITY
   #endif
   #ifndef LANBAI_FOG_OWN_CAP
   float _FogCap;
   #endif
   #ifndef LANBAI_FOG_OWN_HEIGHT
   float _FogHeightFalloff;
   #endif
   #ifndef LANBAI_FOG_OWN_DENSITY
   float _Udon_FogDensity;
   #endif
   ```
   （不要把 `_Udon_FogDensity` 改成无条件声明：TentacleSway 第 486 行自己也声明了它，会变成重复定义。）头注、`给总控.md` §2 第 2 条跟着改；`tests/` 里加“只有 cap”“cap + density（TentacleSway 的情况）”“三个都有”三个用例。

2. **共用的 `_Udon_*` 只防了 `LanbaiGateSky.cginc` 一家**（`LanbaiSky.cginc` 42–49）。任何自己声明了其中一个全局量的 shader（比如远潮 v2 的 `float4 _Udon_TearPos;`）再 include `LanbaiFog`，就是重复定义（补充测试 D）。门的钩子也因此两头都不通：TentacleSway 的 `#if defined(LANBAI_FOG_INCLUDED)` 要求 LanbaiFog 先 include，但先 include 又和 GateSky 的无保护声明撞（测试 F）；后 include 则钩子永远不生效。
   **这是全片的结构问题，不只是天空的**（海的接口里也会有同样的撞名）。我的建议：在 `Common/Shaders/` 加一个 `LanbaiGlobals.cginc`，**登记表里每个 `_Udon_` 全局量都在这里声明一次，每个名字自己一个 `#ifndef LANBAI_DECL_<名字>` 保护**，所有包只 include 它、不再自己写 `_Udon_` 声明。我已经把这个提案写进 `Engineering/给总导演.md`（谁来写、门的 GateSky 怎么改要总导演定）。v1.1 里你先做到：`LanbaiSky.cginc` 里每个 `_Udon_` 名字单独保护（`#ifndef LANBAI_DECL__Udon_TearPos` 这种），等 `LanbaiGlobals.cginc` 定了再挪过去。

3. **“设没设”用 `_Udon_FogDensity > 0` 判断，淡到 0 时会跳回 RenderSettings 的密度**（`LanbaiFog.cginc` 46–49）。圣经 §1.6：“关”= 密度 0，雾 2–6 秒交叉。一个驱动把雾从 0.0006 淡到 0 的最后一帧，密度会从 ~0 跳到 `RenderSettings.fogDensity`（本地 `LB_Journey` 一直在写它，门内 0.0035）。`_Udon_FogBandColor.a`、`_Udon_HorizonColor.a`、`_Udon_FogShape.y`、`_Udon_FogBelow.x < 0` 也是同一类“值兼作开关”。
   **改**：开关和数值分开。`_Udon_FogDensity` 改成 `float4`：x = 密度、w > 0 = 已设（这样 x = 0 就是真的没有雾）；颜色类的 `.a` 已经是这个思路，保持，但在 README 里写清“淡出时只动 rgb / x，不动 a / w”。

4. **模型 A / B 是离散的开关（`_Udon_HorizonColor.a` 1 / 2），两幕之间雾色没法 2–6 秒交叉**（`LanbaiSky.cginc` 131–153）。第 4c → 5 → 6（光带 → 渐变）、8 → 8b → 9 都要换模型；`a` 从 1 跳到 2 那一帧整片雾色换函数。
   **改**（任选一种，推荐第一种）：(a) 加一个 `_Udon_FogModelMix`（0 = A，1 = B），两个模型都算、按它 lerp——代价是交叉的那几秒每像素多算一份，平时用 `[branch]` 只算一个；(b) README 里写死“换模型只能在遮挡下（黑、白、入云、水面）”，并逐个列出全片哪几次换模型、各在哪个遮挡里。

5. **表面着色器的用法在 ForwardAdd 里会把地平线色加一遍**（`README_Fog接口.md` §1、`LanbaiFog.cginc` 21 行、`tests/T_SurfaceFinalColor.shader` 12 行）。`finalcolor` 在每盏像素灯的 ForwardAdd pass 里也会跑，`lerp(col, horizon, f)` 在加法 pass 里等于每盏灯多加一份 `horizon × f`。门的 TentacleSway 刚加了 `noforwardadd` 所以没事，但车厢、宫殿、路灯都是表面着色器、都有实时灯。
   **改**：文档里的范例写成
   ```hlsl
   void lanbaiFog(Input IN, SurfaceOutputStandard o, inout fixed4 color) {
   #ifdef UNITY_PASS_FORWARDADD
       color.rgb = LanbaiApplyFogAdditive(color.rgb, IN.worldPos);   // 加法 pass：只衰减，不加雾色
   #else
       color.rgb = LanbaiApplyFog(color.rgb, IN.worldPos);
   #endif
   }
   ```
   并加一个 ForwardAdd 的测试用例。

6. **本地要的数还没有**（`README_Fog接口.md` 70 行把“每幕的参数组”推到以后）。`CONTROL_总控.md` §6 第 13 条：JSON / README 里没有的数，本地会自己推。现在每个用 `LanbaiFog` 的包都只能靠门的默认值。请在 `Sky/` 下出一个 `FogPresets.json`（每幕一组：模型、近 / 远 / 天顶 / 天底色、带宽、shape、below、密度、cap、高度衰减、过渡的时刻与秒数），驱动和本地都从这一份取。第 4 幕那一组就是门的默认值，先写进去。

## 二、建议

- **第 4 幕的触发量**：你在 `给总控.md` §2 第 3 条自己已经指出，第 4 幕没人写 `_Udon_FogBandColor` 时，走 `LanbaiFog` 的新 shader 会退回 `RenderSettings.fogColor` 的平均色，而不是光带；等价核对里是手动把它设上的，所以核对没暴露这一点。门的驱动（`GateClouds/Runtime/LanbaiGateClouds.cs`）现在没写它。我会在门的审查意见里请她写；你这边建议把退回条件放宽：`_Udon_TearPos.w > 0`（门的驱动一定写）时也当作“第 4 幕”，用门的默认值。
- **第 4 幕的雾色比门少了月晕**：门的触手雾色是 `LanbaiBand + 0.35 × 月晕（+ 伤口空气）`（`LanbaiGateSky.cginc` 118–129 的 `LanbaiGateFogColour`），`LanbaiApplyFog` 只有光带。门以外的东西（以后的云卡、海……）在月亮旁边会比触手的雾暗。README 里写清这个差别，或者提供 `LanbaiApplyFogEx(col, pos, extraAir)` 让第 4 幕的用户自己加。
- **`_FogHeightFalloff` 的含义和圣经、和门不一致**：这里是“以眼睛高度为基准的密度衰减，再封顶”（81–88 行；默认基准 = 眼睛高度，所以站起来雾就变），门的 `_FogCap` 是“距离门控、0 = 没有雾”。圣经 §1.6 要的是“远处的巨物不比同仰角的天更亮”。建议：默认基准用 `_Udon_FogBase` 并要求驱动写（地面世界 = 地面高度，第 4 幕 = 云顶 `_Udon_CloudTop.x`），不要跟着头动；README 里写一张“门的 `_FogCap` ↔ 这里的 `_FogCap`”对照。
- **性能**：`LanbaiApplyFog` 每像素约 200 个标量运算、约 10 个超越函数（asin、两次 acos、三次 normalize、pow、三次 exp、smoothstep），cube 分支没有 `[branch]`（fxc 可能两边都算、cube 一直采样）。不透明物一层大约 0.15 ms @ 9 MP，透明叠 4 层就是 0.6 ms——在第 4 幕的热点里是要算进去的。建议：(1) 模型分支和 cube 分支加 `[branch]`；(2) 给粒子 / 透明卡一个逐顶点的版本 `LanbaiFogVertex(posWS)`（输出 f 和雾色，片元里只 lerp）；(3) README 写上每像素开销，账本会用。
- 模型 A 的两个 smoothstep（99、106 行）在驱动给了相等的两端时会除零（`CONTROL_总控.md` §6 第 3 条）；模型 B 已经防了，A 也防一下（`max(y, x + 0.1)`）。
- 颜色全局量写明 Udon 用 `SetGlobalVector`（线性值原样进去），**不要用 `SetGlobalColor`**（线性工程里会再转一次，见 `Engineering/给总导演.md` 里 bloom 颜色那条，同一个原因）。
- 每幕的全局量要有“交接规则”：前一幕写的值会一直留着（全局量不会自己清零）。写进 README：每个驱动在自己的时间窗开头把它用的全部雾 / 天全局量写一遍（包括 `.a / .w` 开关），不能只写变化的那几个。
- 登记表：`_Udon_FogBase`、`_Udon_NadirColor`、`_Udon_FogShape`、`_Udon_FogBelow`、`_Udon_FogCube`、`_Udon_FogCubeParams` 还没登记（`Engineering/ledgers/globals_report.md` 是自动对账的结果）；`_Udon_HorizonColor` 原来登记的含义是“地平线色”，现在 a 兼作模型选择，登记时写清。
- `check_shaders.py`：(1) 会去展开注释里的 `#include`（对 TentacleSway 原样跑会 FileNotFoundError）；(2) 没编过 `USING_STEREO_MATRICES`（SPS-I）那一支，`LanbaiCentreEyePos` 的立体分支没测到；(3) 没编 FOG_EXP2 / FOG_LINEAR / ForwardAdd 变体。补上。
- “不设任何量时和 Unity 内置雾一模一样”不完全对：这里用到相机的**径向距离**，Unity 内置雾用的是**视深**（屏幕边缘差得最多，90° 水平视场的角上约 1.7 倍的距离）。README 改成“密度和颜色相同，距离按径向算（更正确，VR 里转头雾不变）”。
