# 第 3 幕破云（U6k 129.10）的跳变 · D-50 #1

写的人：云端子会话「天空」，2026-10-31。**没在 Unity 里编译过、没在 Unity 里复测**（要阿白点 `蓝白/Sky/Build Sky` 重建驱动的表以后，按同一个 sweep 的 x09 再量）。

## 复现：是谁跳的

- 阿白 10-26 的全片 sweep（`FromLocal/transitions_sweep/20261026-023256/sweep/x09/frames.csv`）：整帧对数平均亮度 129.009 → 129.101 一帧 −6.694 → −5.686，**+1.008 EV**，之后一直平（129.1 → 133.0 只再升 0.02 EV）。
- 天空的驱动 `Lanbai_SkyDriver_Acts1to3` 在 129.10 从 `overcast_rain_night` **硬切**到 `moon_night`（表里 fade = 0，当时按“云里、遮挡下”做的）：天和雾（`_Udon_Fog` 0.009 → 0.00035）同一帧换掉。
- 在 CPU 上跑真的 `Lanbai/Sky`（主座位正前方 90°、S3 调色、只有天）：这一切是 **+1.63 EV**。Unity 的整帧里有车厢，天占一部分，量到 +1.008（比例约 0.62），对得上。
- **跳的是天空的驱动。** 另外：Unity 的曲线在 129.1 以后是平的，看不到 `EXPO_UP` +0.5 EV 的 0.6 秒升起和 3 秒衰减。说明 Unity 里这时 Director 的 `EXPO_UP` 包络没有起作用（或被别的写回了），这一条要总工程师查。

## 修法（照圣经 §6·3c 的缓开）

`moon_night` 这一条的淡变 0 → **2.5 秒**（`Sky/Tools~/render/make_presets.py` 的 `driver_tables`，生成进 `Sky/SkyPresets.json` 的 `drivers`）。从 129.10 起 `overcast_rain_night.ApplyBlend(moon_night, smoothstep)`：
- 天在 2.5 秒内淡开。这是立方图 → 程序化天的淡变，走 v1.3 的按方向混合，天顶先、地平线后，在对数空间里，没有扫过的边。
- `_Udon_Fog` 0.009 → 0.00035 跟着同一条曲线走。圣经写的是雾 2.5 秒 ease-out；这里是驱动统一的 smoothstep，时长一样。
- 月、星（`_Udon_StarGain` 0 → 0.015）一起淡进来。
