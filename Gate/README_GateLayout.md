## 1. 坐标约定（先看这个）

- Unity 世界：米，Y 上，**车固定在原点、车头朝 +Z，世界往车后移动**（与 `gate_context.md` 相同）。
- **GateRoot 本地坐标**（门里一切都是它的子物体，除了近处 3 条与后窗月之光环，§4.6、§8）：
  - 原点 = **进入点**：U9 时车的原点穿过裂口平面的那一点，在裂口轴线上、**云顶以上 150 m**（= U9 时裂口高 1 000 m 的 15%）。
  - x 右（从车里看）、y 上、z 向前。**裂口面朝 −Z（朝车）。** 云顶在 GateRoot 本地 **y = −150**。
  - 设计坐标 CF（裂口脚为原点，x 右，y 远离车，z 上，云顶 z = 0）→ GateRoot 本地 = `(cx, cz − 150, cy)`。
- 每个实例：实例化 `GateArms_v3.fbx` 里的 `<id>`（带 LODGroup），挂在 GateRoot 下，`localPosition = position`、
  `localRotation = rotation_xyzw`（x, y, z, w）、`localScale = scale`（v4 的自定义臂都是 1）。

## 2. GateRoot 怎么随时间走（timeline 秒，t = 0 出发）

乐句（`cues.md` 实测）：U6 133.80 · U7 150.30 · U7b 155.10 · U8 166.15 · U8b 167.90 · U8c 171.40 · U9 179.55。

```
v_g      = 2700 / (U9 − U6) = 59.0164 m/s          （恒速，不做 ease：一切都扎根在云里，世界一减速就会在云面上“滑”）
h_bus(t) = 40                                       U6 − 20 ≤ t ≤ U6
         = 40 + 20·ss((t − U6) / (160.50 − U6))     U6 … 160.50
         = 60 + 90·ss((t − 160.50) / (U9 − 160.50)) 160.50 … U9      （峰值竖直加速度 1.49 m/s²）
GateRoot.position(t) = ( 0,  150 − h_bus(t),  59.0164 · (179.55 − t) )
GateRoot.rotation = 0，scale = 1
```

- GateRoot.z：U6 2.70 km、U7 1.73 km、U7b 1.44 km、U8 0.79 km、U9 0。y：云顶在世界 y = −h_bus(t)。
- **激活时间改了（技术 B1）**：`GateRoot.SetActive(true)` 在 **t = U6 − 20 s = 113.80**，车还在白云遮挡里（圣经 §1.9 / §6·3）。
  此时所有巨物都**已经站好**（终态），被各自的 `_Reveal = 0`（renderer 关）和云塔藏住；上一轮 63.8–123.8 s 的“在雾里升起”全部删掉。
  激活之前开始的升起（巨像 2 从 121.8 s、两只手从 130.8 s）：激活时把它们放在 t = 113.8 的姿势上即可（它们那时都还在云下或 reveal = 0）。
- 现在 `LB_Builder_Gate.cs` 的 `z = lerp(700, 0, k)` **整段换掉**；U9 进入后交给 4c。
- `ReferenceCamera` 的 **far plane ≥ 14 000 m**（圣经 §1.4 是 45 000；near 0.05）。现在是 7 000 m：U7b 时远潮在 5.7–13.3 km、背景巨物在 3–8 km，会被裁掉（技术 M12）。

### 2.1 每帧要写的全局量（Udon，示意，未编译）

```csharp
float t = Timeline();
float ss(float x) { x = Mathf.Clamp01(x); return x * x * (3f - 2f * x); }
float hBus = t <= U6 ? 40f : (t < 160.50f ? 40f + 20f * ss((t - U6) / (160.50f - U6))
                                         : 60f + 90f * ss((t - 160.50f) / (U9 - 160.50f)));
gateRoot.localPosition = new Vector3(0f, 150f - hBus, 59.0164f * (U9 - t));
float H = TearH(t);                          // JSON timeline.tear_H_knots，单调 PCHIP（v4 多了 (160.5, 715)）
tearRoot.localScale = Vector3.one * (H / 1000f);
VRCShader.SetGlobalVector(_idCloudTop, new Vector4(-hBus, 0f, 0f, 1f));                 // 云顶
VRCShader.SetGlobalVector(_idTearPos, new Vector4(0f, -hBus + 0.4f * H, 59.0164f * (U9 - t), 1f)); // 裂口核心
VRCShader.SetGlobalVector(_idTearH, new Vector4(H, 0f, 0f, 1f));                        // 新：雾色里光晕项的尺寸
VRCShader.SetGlobalVector(_idMoonDir, new Vector4(-0.2059f, 0.1392f, 0.9686f, 1f));     // 新：朝月亮（雾色月晕项、轮廓）
VRCShader.SetGlobalFloat(_idGateTime, t);    // 远潮升起
// 每个有 reveal 关键帧的实例（§4.1）：
float rv = RevealAt(inst, t);                // keys 之间 smoothstep
inst.renderer.enabled = rv > 0f;
if (rv > 0f) { mpb.SetFloat(_idReveal, rv); inst.renderer.SetPropertyBlock(mpb); }      // 同一个 MPB 里还有 _Phase
```

**`Start()` 一次**：每个 renderer 用 MaterialPropertyBlock 设 `_Phase = instances[i].phase`、`_Reveal = 1`（MPB 不序列化，不能在编辑器设）。
其余材质参数**全部写在每个实例的 `material` 里**（§5），可以按“种类”做 8 个材质 + MPB 覆盖 `_FogDensityScale`。

## 13. 已知问题 / 还弱的地方（诚实版）

1. **还不是“让人透不过气”的画。** 第 6 轮去掉了最便宜的几个读法（地平线上的草、鸟爪手指、从上框垂下来的线、通向镜头的“河”、梯子一样的拉链线、根部的条形码带），
   主视觉现在读作：“两只从云里斜伸出来的手，指尖越过撕开的白去勾对面的布；右边一根压住画面的黑柱；左边月亮被拿走一半；云塔给出纵深”。
   但它仍然是**少数几个大剪影 + 大片灰蓝的雾**，没有圣经那句“成百条黑色的巨臂在光雾前涌向它”的数量感。
2. **远潮在主视觉与 U7 里几乎看不见**（§10 的像素数）：v3 图集 + 新摆法去掉了“草”，但它们在 5–12 km、被云塔与地平线云团挡住、又在雾里。
   试过两种让它出现的办法（`wip/r4/tide_cmp.png`）：小而清楚时它们是地平线上的一排草；完全升起、放大 1.8 倍时它们从云塔后面
   拱出来，读成一片**棕榈叶 / 蕨叶**（所有剪影朝同一方向卷），还挡住了月亮。两种都比“看不见”更糟，所以这一版远潮在主视觉那一刻
   只升起了一小部分、藏在云后。真正的解法大概是换掉公告板：用真的低模臂（每条姿态不同、按深度分层的雾）做远潮，这一轮没有做。
3. **手**：横跨白色的两根鞭梢是这一轮最好的变化（勾住对面唇边、末端下卷），但前臂仍偏细、被雾压成扁平的带子，远看仍有一点“长腿”的读法；
   U8 + 3.5 时两根鞭梢在白色中间**碰在一起**，连成一个 “W”，而不是交叉。抓在布上的另两根手指只有在 1:1 才看得出。
4. **翻布**仍是一块皱的浅灰东西（外面 = 天色，里面暗），读作“揉皱的纸 / 石头”多于“被拉开的丝绸”；手指“把布顶起来”的形变看不出来。
5. **Engel** 读作右上角一根斜的暗梁，不是“苍白的天使”；它垂在透镜前的手只是透镜顶上一条暗带。
6. **裂口**：核心是一片平的白（v4 的内层薄纱很淡）；脚下有一圈暗的“毛边”（云里的纤维 / 脚部淡出）；光晕 C\* 只有 ~15–23（圣经 #5B57A1 的 45 在灰色光雾带上到不了）。
7. **U7 的 APL 只有 ~32**（圣经 36–42）：通用车壳占画面 ~46%，透过玻璃是 ~45。没有用抬管灯去凑；真车进来以后要重量。
8. **云海**：光池 L\* ~41（目标 30–36）、朝月的云仍略带紫（C\* ~10，目标 ≤ 6）。
9. **车壳仍是通用灰盒**（没有你们的车 FBX）；U8b 的车厢墙仍是灰的；目的地牌「蓝白」调暗了，但仍是画面里一个清楚的字块（这是有意的：它是车的名字）。
10. **后窗**：后窗组的臂读成插在云里的弧（鞭梢又落回云里），不是“握拢的手”；月之光环很淡。
11. **运动的偏离**（§12）：远潮冠中位 0.45°/s、最大 0.85°/s（圣经 0.3）；手 ≤ 0.87°/s（约定 1.0）。巨物都 ≤ 0.5。
12. **Unity 里的根部化开**（shader v2.5 `_RootDissolve`）是 6 m 世界噪声的 clip：在 2 km 外一个噪声格不到 1 px，可能闪烁；若闪，就把 `_RootDissolve` 设 0、靠云卡挡住根部。
13. **shader / C# 都没在 Unity 编译**，只过了 slang 的语法 / 类型检查（TentacleSway v2.5 三个 pass、Tide v2.2、Tear v4 八个部件）。
14. 车高、近层长度、巨物尺寸、远潮雾与速度、光雾带仰角都偏离了圣经表（§12 的修订提案，**待用户批准**）。
