## 4. 运动

## 6. 已知弱点（诚实版）

- **参考帧里的海是替身**（水色 + 菲涅耳 × 天的倒影，没有浪、没有闪光路径的钳位）；Unity 里是海会话的 `Lanbai/Sea` ABOVE。海镜那几张只看构图，不看海本身。
- **车壳是角度窗的占位**（标准台 `bible_v2` + D-12 的门），内壁是暗灰，没有车厢里的金色光带、没有窗帘；APL 因此比真车厢偏低。D-28 的新车壳 `paz672` 到了要复量。
- **云体没有门那套“皮”和银边**（门的云海是月光逆光下的银边；晨的低日从侧面照，主要是受光面和影子，这一版先不做）。
- **性能没量过**（评审 r1 S7：风险高）：每个往下看的像素最多 96 步、每步 3–4 次取样；在峡谷里、云盖下面往上看的像素也要整段步进；峡谷里水平看出去基本跑满。r2 的深度 pass 降到 48 步 + 2 次二分（`_MarchDepth`）；谷里的雾 r3 是 16 步、每步 3 次取样（只在雾的高度带里）。请按 §0 第 5 条量一次。降档表（先后）：`_March.x` 96 → 64 → 48；`_MarchK.w` 4 → 3；`_MarchK.z` 250 → 400（远处步子大）；`_MarchDepth.x` 48 → 32。另外请在 Unity 里确认：renderer 的 `shadowCastingMode = Off` 时 ShadowCaster pass 还进不进 `_CameraDepthTexture`（进不了的话云卡贴着云原的软边会失效，谷里的雾也会穿过云体：那就改成 On + 不接收阴影）。
- 谷里的雾不是一个真的体积：朝太阳的楔形是从车的位置定的、只对地平线以上的视线开。所有人都坐在车里，所以看起来是对的；只有从车外看才会发现它跟着车。
- 峡口从车下方往两边裂开（`s0` 在车后 2.2 km），281.86 → 287.86 之间边缘在脚下展开；请在头显里看一眼舒不舒服（评审 r1 建议项）。
- 步进没有门那样的 LanbaiHash13 抖动，远处的墙和云原可能有分层。
- 云塔应答在参考帧里是整张卡 +0.7 EV（Unity 里也是：卡没有单独的“冠”的遮罩），所以是上限。
- 条带 `CloudSeaV2_2_dawn` 还在渲（地平线一圈先全用条带 1）。
- **顺光时云底偏暖（复审遗留）**：试过在颜色求解里压它（权重 30）：云底降到 `#C5B4B0`（C\* 6.7），但云顶掉到 `#E9DAD1`，日色温 3111 K，色板的桃金 `#F6DCC4` 没了。顺光时云底是**受光面**不是阴影（圣经 §1.3 第 2 条说的是阴影），所以保留原解（云顶 `#F5DCCA`），这条写成和评审的分歧。
- 雾色在参考帧里是“这片天在该方位、仰角 ≥ 1° 的颜色”，Unity 里是 `LanbaiHorizon` 的模型 B：两者接近，不是逐像素一样。
