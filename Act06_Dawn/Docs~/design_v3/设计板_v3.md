## 4. 性能预算（圣经 §1.9：RTX 3060 级、约 9 MP @ 90 Hz；世界 ≤ 5.3 ms，其中阴影平行光约 1.0 ms；透明持续 ≤ 4 FSE，车厢玻璃 0.7 FSE）

第 6 幕最重的是 6b / 6c：云墙 + 海 + 云盖同屏约 30 秒（圣经的热点）。

| 项 | 预算 | 怎么做到 |
|---|---|---|
| 体积云（A、B、塔一遍画完） | **≤ 1.8 ms** | 只画车窗里的像素（代理在车厢后面，车厢先写深度）。主座位的画面里窗大约占一半。平均 ≤ 20 次 3D 取样 / 像素：近处 ≤ 24 步，进云后步子缩小，透过率 < 0.03 早退；朝光每 2 步 1 个样本，加上用二维覆盖率算的“上面那层有多厚”的阴影项；8 km 外走便宜路径（2D 覆盖率 + 1 次 3D、不做细节，4–6 步）；二维覆盖率是 0 的地方只取 2D |
| 海（ABOVE，含反射立方图） | ≤ 0.6 ms | 不变 |
| 天 | ≤ 0.2 ms | 不变 |
| 阴影平行光（太阳） | 1.0 ms | 圣经的数，不变 |
| 车厢、光柱、尘 | ≤ 1.5 ms | 车包的数 |
| **合计（世界）** | **≤ 5.1 ms**（上限 5.3） | |
| PPv2 | ≤ 1.2 ms | 不变 |
| 透明（FSE） | 体积云约 0.5（只在窗里）+ 车厢玻璃 0.7 + 光柱 0.3 + 尘 0.1 ≈ **1.6**（上限 4） | 体积云只是一层 |
| 显存 | 约 10 MB | 128³ RGBA8 带 mip 9.1 MB；一张 1024² 的覆盖率图 1 MB（也可以不用图，shader 里按参数算） |
| 下载 | 约 3–9 MB | 3D 纹理不能 crunch；要省就压成 BC4 × 3 |
| Udon | ≈ 0 | 每帧写一个时钟全局量；主光的遮挡按透过率表插值 |

**砍的顺序**（auto-lite，圣经 §1.9）：
1. 近处步数 24 → 16；
2. 朝光 1 → 0（只用二维覆盖率的阴影项）；
3. 细节噪声关；
4. 远处的便宜路径从 8 km 提前到 4 km。

这些都是估计。要在本地 3060 级的机器上用 `act06_test` 录一段 6b / 6c（285 → 320），开 GPU profiler 量过才算数。

## 8. 没做的 / 不确定的

- **画面：** 是 numpy 参考步进，朝光 4 个样本、步子细，比 shader 好看。shader 按 §4 的预算会粗一些，差多少要在 Unity 里看。
- **车穿进云团：** 车在谷里会穿过一两团稀的云（参考里 290–303 有），在 B 层（约 326–332）也会穿过。进云那一下的亮度变化要按 flashcheck 量；舒适包络（眼前 18–40 m 内密度渐到 0）沿用阿白的。
- **云的流动：** 风 2–5 m/s，在单帧里看不出来。动态要在 Unity 的序列里看。
- **配色：** 光照用的是晨卡解出来的颜色 × 两个系数，只在 266 的画面上粗校过（阴影接近 `#8593AA`），没有按圣经的色板逐项解。
