## 阻断

### B1 · 穿过谷底薄雾时画面一下子变亮，超出爬升律（§1.8）
谷底的“薄雾”（−1100 → −1134）在场里是不透明的硬面。眼睛进去的那一刻（≈304.4）窗外一帧就变成满屏均匀的桃色（≈`#EECDB6`），之后一直是这块平涂，直到 305.43 出云盖底。用 `act06_ref.render` 每 0.05 s 一帧量（全画面平均相对亮度的 EV）：

| 机位 | 结果 | 限 |
|---|---|---|
| 正前 | 304.15 → 304.40：**+0.77 EV / 0.25 s**（304.35 → 304.40 一帧 +0.40） | 0.5 |
| 车门 D-12 | 304.15 → 304.40：**+0.69 EV / 0.25 s** | 0.5 |
| 天窗 | 304.35 → 304.40 一帧 +0.42 EV | — |

画面上也不对：圣经要的是“穿过”云盖，现在是约 1 秒的一块平涂色。`act06_flash.py` 只核查了 252 → 268；§1.8 窗口 (b) 要的是 99–368 整段（含云峡、云盖、F1b1）。
要做：薄雾按眼睛在雾层里的深度做成有密度的过渡（进入时 EV 线性、≥ 0.25 s 内 ≤ 0.5 EV），或者把谷底改成眼睛到之前就能看穿；把 300 → 322 段加进 `act06_flash.py`，三个机位都跑 flashcheck。F1b1 那段我量过没问题（正前 318.4 → 320.4 +0.28 EV / 2 s）。

### B2 · 云峡没有“向阳的左墙”
峡谷轴是方位 25°，太阳是 30°，只差 5°：左墙的 N·L ≈ sin 5° × cos 5.8° ≈ 0.09，基本是擦射。`hero_t296.00.png` 左墙中值 `#747A8C`（L\* 51、C\* 11、h 279），这是背阴色；亮的只有凸起上的金色碎斑，放大看像岩石或雪坡上的鳞片和火苗，读不出“菜花”状的云。圣经 6b 写的是“向阳的墙金 `#F3D2B0`、背阴的墙藍灰 `#8593AA`”，README 也说“左墙向阳”，但画面上没有。
还有一个舒适问题：这些金斑高对比、很碎，墙以约 4°/s 移动；步进没有抖动，墙的命中点只靠 4 次二分（250 m 一步时误差约 ±15 m），两只眼各自步进，所以会爬、会闪，左右眼还可能不一致。另外墙的凸起是 (沿轴, 高度) 的函数，法线却只用 xz 的有限差分，高度方向的起伏没进法线，这也是碎斑的来源之一。
要做：峡谷轴和日向错开约 20–30°（仍然朝太阳开、日光仍能沿谷射进来；云唇和朝日的边要重解），或者给墙一个不靠几何法线的受光项；凸起的法线带上 y 分量；墙的高光做亚像素淡化（D-25 对亮边的要求）。

### B3 · 地平线一圈的接缝在主镜头里是两根褐色竖条
`hero_t266.34.png` 在 x ≈ 0.33 和 0.66（方位 ±18°）各有一根模糊的暗褐色竖条，中值 `#C18D77`（h 49、C\* 26）。`door_d12_t266.34.png` 里同一根就在太阳左边（x ≈ 0.39）。位置正好是 Ring_00 和左右两张卡的重叠带：卡宽 9 km、半径 13 km，半角 19.1°，每 36° 一张，重叠在 16.9°–19.1°。圣经“要避免：发褐”，而且它出现在 F0s 的定格画面里，紧挨着车门里的太阳。其余几道接缝（54°、90°……）在这些机位里被立柱挡住了，也要一起查。

## 应改

**S1 · 云原和云塔的阴影是“粉灰 / 灰紫”，读不出“右侧桃金、左侧藍灰”。** 266.34 正前：左侧云原 `#9797A2`（h 291、C\* 6），右侧 `#B0A0A2`（h 10、C\* 6），云塔背阴 `#9D939D`（h 325、C\* 7）。数值规则（h 285–330 且 C\* > 12 ≤ 2%）过了，但圣经 §1.3 第 2 条、§6·6 的色板（云影 `#8593AA`，h 272、C\* 14）和“要避免：发灰 / 发紫的云影”没守住。README §6 把这条写成和上一轮评审的分歧，请总导演裁；我倾向于改：阴影 h 265–275、C\* ≥ 12，云顶受光面仍保留 `#F6DCC4`。312 的海和雾也是粉灰（`#85797C`），圣经说的是“海是藍灰的”。海是替身，这里主要是雾 / 地平线的颜色。

**S2 · 云盖底面有两种着色，分界是带像素噪声的锯齿，还有深色细裂纹**（`hero_t312.00` 和 `hero_t320.50` 左上，放大能看到）。下降时这条分界会移动、闪烁。怀疑是 `under` 的判定（`abs(p.y − bottom) < abs(top − p.y)`）或区域软边在某些像素上翻转，需要查。

**S3 · APL 和 §2.2 的差距。** 266.34 正前 124.7（110，+13%，README 自己也说真车厢进来以后会超过 15%）；345.36 是 113.1（94 → 90，**+20–25%**，超出 ±15%）；312 是 86.1（这一段从 74 起，+10–16%）。S6 一直保持到入水，不变调色，所以不能用 postExposure 去修某一拍，要在场景里解决：天光增益、雾、海。

**S4 · 黑 → 晨的爬升余量太薄，量法的说明也混了。** 正前 2 s 窗是 1.74–1.75 EV（限 1.8；圣经按最亮视向设计的值是 1.68–1.70），而这还是暗灰占位车厢、没有金光带的结果。这说明调色的 toe 让实际速度比公式快。建议每方向时长加到约 9.0 s，太阳扇区的 lead 压到 3.2，仍在 F0s 前后落定；paz672 车壳到了在头显里复跑。核查本身是成立的：静态 266.34 帧 + 遮罩数学 + S6 调色含 bloom，这 14 s 里画面几乎不变。但 README 表里的“峰值 APL 149 / 117”是 flashcheck 的 (平均线性亮度)^(1/2.2)，和 §2.2、refs json 用的平均 luma（125 / 83）不是同一个量，要标清楚。

**S5 · 海镜没有反射立方图，也没有回退。** `LanbaiSea.cginc` 的 `LanbaiSeaCube` 直接采 `_Udon_ReflCube`，材质里没有回退；`reflCube` 不赋值就是未绑定的全局立方图（黑 / 灰）。README 和 `给总控.md` #2 说的“没有它时海用自己材质里的回退”不成立，而 6c / 6d 的海镜全靠它。先给一张临时的：dawn 预设的 HDRI，或在编辑器里从海面附近现烘一张，要含云盖底面。再把文档改对。

**S6 · 跳出窗口时遮罩没有交还。** `LanbaiActivate(false)` / `HandBack()` 不调 `overlay.Hide()`。往回拖到 252.64 之前（门内只在 248.39 → 252.64 写黑），或者测试时从 260 直接跳到窗口外，遮罩会停在半黑的曲线状态，下一个驱动不会清。HandBack 里如果遮罩是自己写的（`!_overlayHidden && _lastT >= tPreroll0`）就调 `Hide()`。另外往回小于 0.5 s 的拖动不会重新挂上遮罩，影响很小。

**S7 · 性能没量，风险高。**
- 每个往下看的像素最多 96 步，每步 3–4 次贴图采样，外加 atan2 和 3 个 exp。
- 在峡谷里、云盖下面，往上看的像素也要整段步进。
- 在峡谷里水平看出去时，步长只按竖直余量算，而墙是横向的，所以基本要跑 60–96 步。
- ShadowCaster pass 为相机深度图把整个步进再跑一遍：深度预渲染和颜色 pass 一样贵，等于翻倍。

§1.9 的世界预算是 5.3 ms，6b / 6c“云墙 + 海 + 云盖同屏”本来就是点名的热点。量之前先给一个便宜的深度 pass（步数减半、只用粗 LOD），再列一张 `_March.x` 的降档表。另外请在 Unity 里确认：`shadowCastingMode = Off` 时这个 renderer 还会不会进 `_CameraDepthTexture`。门的云海是同样的做法，我没看到实测记录。

**S8 · 海镜（6d）没有画面证据。** `hero_down_t345.36` 几乎全是车厢地板的占位，只在右上角露出一小块海。至少补一张靠窗往下看、或侧窗往下看的。海是替身也要能看构图：倒影里的云缝、被照金的云盖底面、闪光路径比日盘低 ≥ 1.3 EV。

## 建议

- 太阳被挡在 304.64，挡住它的是谷底的薄雾；圣经写的是 305.4、由云盖挡住。修 B1 时一起对齐。
- 太阳仰角 5.8°（D-12 写 6°）、朝日的边 4.58 km（圣经 4.4 km）：都已经写进文档，请总导演终审时一句话确认。
- 数据只有一个来源（CONTROL §6 #13）：驱动的 `leadSun` 3.3、`dawnT` 8.65 是 builder 写死的，Layout 里是 `stagger.sun_sector` 3.5、`dawn_per_dir_s` 8.7；瓣的方向、半角也没从 JSON 烘进去。请统一。
- 预滚（252.64 → 254.14）的 alpha 是线性插的，不是 Overlay README 写的 EV 线性。这段在地板以下，不计入爬升律，影响很小。
- D-09 的 VR 分支（遮罩曲线按 150 重建）没做。VR 实测 ≤ 150，现在的曲线只会更慢、更安全，记一笔就行。
- 峡口从车的正下方往两边裂开（`s0` = −2.2 km，在车后面）。281.86 → 287.86 之间边缘在脚下以大约 30°/s 展开，圣经写的是“前下方”。请在头显里看一眼舒不舒服。
- 步进没有门那样的 LanbaiHash13 抖动，远处的墙和云原会出分层或带状。
- 贴图的导入设置（sRGB 关、RGBA32、Repeat、各向异性 16）只写在 README 里，builder 没有设 TextureImporter。忘了设，高度就全错，建议让 builder 来设。
- 云塔应答是整张卡 +0.7 EV，而且之后不回落；要只亮冠，需要卡上的遮罩。
- `fogColorGamma` 的默认值 `#C4B8C0` 是圣经里的屏幕色，不是填值；builder 找到预设时会用预设的 `fogColor` 覆盖，影响小。
- 云盖下雾密度降到 0.00003，圣经里没有（圣经是全幕 0.00012）。Layout 里写了，请总导演知悉。
