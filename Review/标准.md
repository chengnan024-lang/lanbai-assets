# 蓝白 · 美术审片标准（v1，2026-10-22）

> 写的人：美术审片会话（`pkg/review`）。小楠 10-22：「总导演，你的画面要人去顶一下啊，审核啊」。
> 这一页定**审什么、怎么量、多少算过**。所有数都出自圣经 v2.1（`Art/ART_BIBLE.md`）；第 4 幕按 `Gate/README_GateLayout.md` §12 的 v2.3（已批的行）。机器可读版是 `Review/targets.json`（由 `Tools~/build_targets.py` 从圣经生成，圣经改了就重跑）。
> 原则：**屏幕目标是法律，参数只是起点**（圣经第 1 条法律）；**美是最高**，能压过美的只有 §1.8 VR 铁律和 §1.9 硬性能预算（PLAN 第五节）。审片不给任何人面子，包括总导演的车厢。

## 0. 流程

1. 每次巡检：`git fetch`，看每个包分支（`pkg/gate-clouds`、`sky`、`clouds`、`sea`、`palace`、`inside`、`mirrors`、`lamps`、`cabin`、`engineering`）相对上次审过的提交有没有新的 PNG / EXR（渲染、迭代图、Unity 截图）。
2. 有新图就开一次审片：
   - **亲自量数**：`Tools~/measure.py`（第 2 节的每一项）；有场景线性的 EXR 就用 `Tools~/regrade.py` 按 PPv2 引擎重新调色，和包自己出的 PNG 对照（第 6 节）。
   - **评审团**（第 4 节）：四个视角各自独立看图 + 一个 640 px 缩略图的陌生人测试。
   - **对抗式核查**：每一条“阻断”另开一个 agent 专门去反驳它；反驳不倒的才写成阻断，反驳得动的降为次要或删掉。
   - 结论写成 `<包的主文件夹>/美术审片意见.md`，推到那个包的分支（第 5 节格式）。
3. 记进 `Review/全片审片总表.md`；主机位过审的图登记进 `Review/overview_sources.json`，重出 `Review/全片总览.png`。
4. 一个包进 main 要**美术审片和总导演都通过**。严重问题、或者我和总导演意见不同，写进 `Review/给总导演.md`。

## 2. 量什么、怎么量、目标是多少

量法全部在 `Tools~/measure.py` 的文件头；定义和门的 `gate_metrics.py`、本地的 `metrics_unity_vs_render.json` 一致（APL = Rec.709 luma 在 sRGB 码值上的平均，0–255），所以三方的数能直接比。

| # | 项 | 怎么量 | 目标 | 不过时的严重度 | 出处 |
|---|---|---|---|---|---|
| M1 | **APL** | 全画面 luma 平均 | §2.2 该段的值 **±15%**（`targets.json segments`）；VR 全画面 ≤ 150（白除外） | 超出 ±15%：次要；超出 ±30% 或方向反了（该暗的亮、该亮的暗，破坏“低谷在高峰之前”）：**阻断**；VR > 150：**阻断** | §1.5、§2.2、§1.8 |
| M2 | **紫** | CIE Lab(D65)，h_ab 290–325 且 C\* > 15；报全画面占比和**最大 8 连通块**占比 | 第 4、4c 幕以外：任何 > 2% 的连通区 = 违规；第 6 幕另加 h 285–330 且 C\* > 12 ≤ 2%；第 4 幕 U7–U8 正前方 C\* > 30 的紫 ≤ 10%，且紫只在伤口附近；第 7b 幕紫贝阙 `#7A4A6E` 是唯一的回声，只在灯旁小面积 | **阻断**（这是全片最硬的颜色纪律） | §1.3 第 4 条 |
| M3 | **不纯黑不纯白** | 三通道都 ≤ `#030409` = 纯黑；luma ≥ 246（`#F4F7FA`）= 纯白；报最大连通块 | 任何 > 2% 的连通区都不许；夜景地板 `#04060B`；红通道不许为 0（夜间 lift 把 0 抬到 `#02060C`）；只有第 5 幕的 3 秒黑可到 `#030409`；小发光体可以裁切 | 阻断（> 2%）；红 = 0 的大片：次要 | §1.3 第 5 条、§1.4 |
| M4 | **一个最亮点** | 最亮 2000 px 膨胀后的连通簇：占 ≥ 5% 的簇数、最大簇占比、外框；L\* > 85 的像素 | 只有 1 个簇，而且在那一幕点名的焦点上（第 3 节“最亮点”一列）；第二个簇亮度接近（ΔL\* < 5）且面积 > 最大簇的 1/3 = 两个焦点 | 两个焦点：**阻断**；焦点放错地方：**阻断**；小的第二簇（反光线、占位车壳）：次要 | §1.3 第 1 条 |
| M5 | **色板** | 每个色板色：画面里最近像素的 ΔE2000（0.1 分位，抗噪）、ΔE < 5 的像素占比 | 命名角色（天、阴影、焦点、主体）ΔE ≤ 5 = 准；5–10 = 漂（次要）；> 10 或该出现的角色不在画面里 = 看情况**阻断**（角色是这一幕的脊柱时，例如晨的天顶藍 `#3E64A6`、暮的中天 `#808AB2`、海的群青） | §1.5 法律 1、§6 每幕色板 |
| M6 | **阴影里只有蓝** | L\* < 25 且 C\* > 6 且 h 20–100 的像素占比 | ≈ 0；暮里阴影是靛石色，暖只在光里 | > 1%：次要；大片暖阴影：阻断 | §1.3 第 2 条 |
| M7 | **上 25% 的 L\*** | 画面上四分之一 L\* 的 p90 | 夜景（1、2、4 的天、9a）≤ 10；光在上面的帧（伤口、天窗、日、斯涅尔之窗）不适用，写明 | 次要（提示天空漏光或雾比天亮） | 门的验收 §10、§1.6 “雾永远不比同仰角的天亮” |
| M8 | **地平线水平** | 拟合地平线（或云海/海面的远边）的斜率 | ≤ 0.1°（1920 宽、90° 视角下约 1.7 px 的高差） | **阻断**（任何倾斜在 VR 里都是横滚） | §1.3 第 6 条、§1.8 |
| M9 | **什么都不碰车** | 看图 + 包的运动检查（离车壳距离、离眼角速度） | 触手 ≥ 8 m、相对速度 ≤ 1.05 d；任何东西不进眼前 0.3 m；只有光带穿过车 | **阻断** | §1.3 第 8 条、§1.8 |
| M10 | **爬升律与闪烁** | 60 fps PNG 序列跑 `python3 Art/tools/lens_tech/flashcheck.py <dir> --fps 60 --hfov 90` | `lanbai_flash_rule: PASS`；除 `FLASH_TEAR` 外 `lanbai_ramp_law: PASS`（0.5 EV/0.25 s、1.0/1 s、1.8/2 s）；按视向录（§1.8 的八段窗口） | **阻断**（铁律，没有例外） | §1.8 |
| M11 | **诗句亮度** | 诗句像素 luma | ≤ 224，无辉光、无描边、无投影 | 阻断（会 bloom） | §1.6、§7.2 |
| M12 | **反照率** | 包里的材质值（看 JSON / 材质表） | 非金属 48–231（例外：黑橡胶 / 漆 / 亚麻 ≥ 38，触手 30–44，湿沥青按 Lagarde）；不超过 235；车身白 ≤ 218；金属 ≥ 150，金属度 0 或 1 | 次要（单项）/ 阻断（主体材质整体偏离） | §1.6 |
| M13 | **调色复核** | 场景线性 EXR 按 `Grading/Tools~/engine/ppv2_engine.py` + `grades_engine.json` 重算（含 bloom），和包交的 PNG 比 | 均值差 ≤ 2 码、p99 ≤ 6 码；不一致说明包的“预览调色”和 Unity 会看到的不一样 | 次要；> 10 码的系统偏差：阻断（图不代表 Unity） | §1.7、`Grading/README_Grading.md` |

**区域的 2%**：1920×1080 的 2% = 41 472 px。工具在 480 宽的降采样上做连通（一个块 ≥ 2% 才算“区域”），同时报全画面占比，零碎的小斑点不算区域违规，但全画面占比很高时要看图。

## 4. 看不出数的那部分：评审团

每次审片开五路（互相看不到别人的意见）：

| 视角 | 问的问题 |
|---|---|
| **圣经与色板的法律** | 第 2 节 M1–M13 的每一项；色板角色在不在、准不准；“要避免”清单有没有踩；数和图一致吗（量法有没有被骗：暗角、占位车壳、bloom） |
| **构图与电影感** | 眼睛先去哪、然后去哪、哪里在抢；尺度读不读得出来（km 级的东西像不像 km）；层次与负空间；剪影；光的方向和质感；能不能当一张电影海报；有没有廉价 CG 感（塑胶、蜡烛、芦苇、传送门、光剑、清漆、等距环节、对称）；**“震撼宏大”有没有** |
| **这一幕的诗、音乐与情绪** | 第 3 节“那句话”在这个乐句时刻有没有被画出来；母题链（§3.3）有没有接上前后幕；**“克制对压倒”**：高峰前有没有 ≥ 10 秒低谷、宏大的东西是不是无声而缓慢、画框有没有随宏大变宽（窗 → 天窗 → 破洞 → 无墙 → 无） |
| **VR 与人在车里坐着看** | §1.8 铁律；在头显里（Index / Quest 2，约 20 px/°）1 px 的轮廓会不会闪、黑压黑看不看得见体量、OLED 黑拖影；近处东西的距离与角速度；车厢作为“安静的画框”；看哪里是自愿的、没有东西强迫你看；地板与休息参照 |
| **陌生人测试** | 只给 640 px 宽的缩略图，不给任何背景、不给文件名：“一句话说你看到了什么，再一句说它让你感觉到什么”。拿来对第 3 节“那句话”。说出“蜡烛 / 芦苇 / 传送门 / 水族箱 / 蒸汽波 / 游戏截图”这类词 = 读法失败 |

**对抗式核查**：评审团的每一条阻断，另开一个 agent，给它同样的资料，任务是“尽力反驳”——误读条文、已被批准的修订覆盖、包已经诚实承认并合理留给 Unity、只是口味、量法错了、夸大严重性。站得住才写成阻断。

## 5. 判定与意见文件

- **阻断**：不改不能进 main。只用于：违反 §1.3 画面语法 / §1.8 VR 铁律 / §1.9 硬预算；屏幕目标的脊柱角色明显偏离；读法失败（陌生人测试说出了反面的东西）；这一幕的那句话没有被画出来。
- **次要**：应该改，不挡合并；下一轮要回应。
- **亮点**：做得好的，写出来让包知道往哪个方向走。
- **判定**：通过 / 有条件通过（只剩次要，或阻断只差 Unity 实测才能定）/ 不通过（有阻断）。
- **回应规矩**（CONTROL §0）：美术审片的意见和总导演的一样要**逐条回应**——改，或者在 README 的“与评审的分歧”里写明理由。我下一轮先读回应再审。

`<包的主文件夹>/美术审片意见.md` 的格式：

```
# 美术审片意见 · <包> · 第 N 轮（<日期>，审的提交 <sha>）
**判定：通过 / 有条件通过 / 不通过**
一句话：……
## 量出来的数（表：图 · APL 目标/实际 · 紫 · 黑白 · 最亮点 · 色板 · …）
## 阻断（每条：编号 · 哪张图 · 画面哪里 · 目标（出处）· 实际（数）· 建议怎么改 · 对抗核查的结论）
## 次要
## 亮点
## 陌生人测试（每张缩略图那一句）
## 下一轮我要看的图
```

## 6. 调色复核（PPv2 模拟）

- 包如果交了场景线性（调色前）的 EXR，审片用 `Tools~/regrade.py` 按引擎重算：bloom（`Art/tools/lens_cine/ppv2.py bloom_layer`，在调色之前加在场景线性上）→ `ppv2_engine.codes`（Neutral 路径、33³ LUT、`Grading/Tools~/inputs/grades_engine.json` 的参数）。这和 Unity 实际看到的是同一套数学（`Grading/verify.md`）。
- 和包交的 PNG 比：均值 / p99 码差、色相漂移；不一致时以引擎为准，包的预览要改用引擎出图。
- 只有 PNG 没有 EXR 的，量调色测试卡那一行（`calib_final.md` §C，±3 码）对不上就要求补 EXR。
