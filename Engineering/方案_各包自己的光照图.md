# 方案：各包自己带光照图（宫殿要烘焙，全片只有一个 LightingData）

写的人：总工程师，2026-10-25。**总导演已裁决（2026-10-25，见文末“裁决”，写进 D-42）**。代码还没写；工具排在测试工具合 main 之后。

## 问题

- 全片是一个正式场景，Unity 一个场景只有一个 LightingData。宫殿 README §4 的做法（只开宫殿的 62 盏烘焙点光 + 2 盏聚光，Bake）会**重烘整个场景**，把别的包已经烘好的光照图全部盖掉；别的包将来要烘，也会盖掉宫殿的。
- 会动的根物体（各幕的根按时间轴移动、开关）：Unity 的光照图本身跟着物体的 uv1 走，移动不怕；怕的是“谁来烘、存在哪、什么时候被别人覆盖”。
- 运行时换光照图（“预烘贴图 + 运行时给 `LightmapSettings.lightmaps` 赋值、给 renderer 设 `lightmapIndex` / `lightmapScaleOffset`”）**在 Udon 里大概率做不了**：这几样不在 Udon 的白名单里（没在 VRChat 里核实过；就算能用，赋值时整片光照图表一起换，几个包同时在画面里就打架）。所以不推荐这条路。

## 推荐：各包的烘焙光写进自己的贴图，shader 用 uv1 自己读（D-32 车厢的做法推广到全片）

车厢已经是这么做的：`_CabinTubeLM` 是预烘好的管灯光照图，`Lanbai/Cabin` 用 uv1 自己采样（D-32），完全不碰 Unity 的 LightingData。推广成全片的规矩：

1. **正式场景不做 Unity 的全场景烘焙**。LightingData 空着（或者只留给真的不动、不属于任何包的东西，现在没有）。各包的渲染器 `Contribute GI` 关、不进主场景的烘焙。
2. **每个包在自己的烘焙场景里烘**（本地做；烘焙场景不进正式世界）：
   - 菜单 **蓝白/Bake/Isolated Bake…**（总工程师做，共用）：新建一个临时场景，只把这个包的根（用包自己的搭建菜单搭）和它的烘焙灯放进去，按包 JSON 里的烘焙参数（宫殿 `PalaceLayout.json` 已经有：Progressive、4 texel/m、各渲染器的比例、Bounces 2、InverseSquared）设 Lighting Settings，Bake。
   - 烘完由同一个工具**提取**：每张光照图存成 `<包>/Generated/Lightmaps/LM_<n>.exr`（HDR，按普通贴图导入：BC6H、线性，不按 Lightmap 类型导入，这样 shader 里不用 Unity 的 RGBM / dLDR 解码），每个渲染器的 `lightmapScaleOffset` 直接**写进它的网格拷贝的 uv1**（uv1 × scale + offset），网格拷贝存进 `<包>/Generated/Meshes/`，材质按“用哪张光照图”分组，属性 `_BakedLM` 指那张图。
   - 结果：光照图跟着包走，跟着根物体动，谁烘都不会盖掉别人的；不需要任何运行时代码。
3. **shader 共用一个读法**：`Common/Shaders/LanbaiBakedLM.cginc`（总工程师写，登记进集成说明）：
   ```hlsl
   // 顶点：o.lmUV = v.uv1;   片元：
   half3 baked = LANBAI_BAKED_LM(i.lmUV);     // tex2D(_BakedLM, uv1).rgb × _BakedLMGain；_BakedLM 没设时 = 0
   ```
   加到包自己的光照上：烘焙的是宫灯这类“只参与烘焙”的灯（D-31 #2 的隐形补光也是这类）；**那一盏带阴影的主光（D-24）照旧是实时的**，不烘进去（烘焙灯的设置里关掉它）。
4. **和现有规矩不冲突**：§1.6“只有一盏带阴影的主光；不加 Mixed 灯；不烘光照探针”照旧；宫殿的 64 盏都是 Baked、只进宫殿自己的光照图；全片的 VRAM 账按包记（宫殿的光照图算宫殿的，账本 §七 的车也一样）。
5. **Directional 光照图**：先不做（宫殿 README 写的是“可选”）；要法线细节的包，以后在同一个工具里加一张方向图、`LanbaiBakedLM.cginc` 里加一行。

## 裁决（总导演，2026-10-25，D-42）

1. **采用**。会动的根物体（门、海、宫殿……）一律用“各包自己的光照图 + uv1 + `LanbaiBakedLM.cginc`”。**静止的站台（第 1、12 幕）可以用 Unity 正常的场景烘焙**，前提是不和这套冲突。
2. **BC6H**。只做 PC；显存照实记进账本（按包记）。
3. **宫殿不等工具**：这一轮先改美术，提取工具到了再接。工具排在测试工具合 main 之后。

### 站台用场景烘焙时，不冲突要守的四条（总工程师补）

场景烘焙一点 Bake，会把**场景里所有开着的 Baked 灯、所有 Contribute GI 的渲染器**都算进去。所以：

1. **各包的渲染器不进场景烘焙**：`Contribute GI` 关（不勾 Static 的 Contribute GI）。各包的搭建脚本本来就该这样建；Isolated Bake 工具提取出来的网格拷贝也这样设。否则站台的光照图里会多出宫殿、门的影子和反光，而且这些物体一动就错。
2. **各包的烘焙灯不留在正式场景里开着**：宫殿的 64 盏 Baked 灯只在宫殿自己的烘焙场景里用；正式场景里不放（关着的灯 Unity 不烘，但容易被人顺手打开，所以规矩按“不放”写）。否则站台会被宫灯照到。
3. **包的 shader 只读 `_BakedLM`，不读 Unity 的光照图**（不用 `LIGHTMAP_ON` 那条路）；站台的 shader 才用 Unity 的。两套各读各的，不叠加。
4. **在正式场景里点 Bake 的只有站台**，由谁点、什么时候点写进 HANDOFF_CHATGPT §G；测试工具加的“烘焙前后检查”改成：Isolated Bake 前后主场景的 LightingData 不变；站台烘焙前后各包 `Generated/Lightmaps/` 不变。

这四条做工具时一起写进集成说明，搭建脚本的检查（`Contribute GI` 关、正式场景里没有 Baked 灯）也加进工具的检查里。
