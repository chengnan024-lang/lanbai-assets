## 1. 坐标与时间

- **世界**：车固定在原点、车头朝 +z（跑步机）。**水的坐标系**：x 右、y 从海面往上（= −深度）、z = 车的前进方向。车的原点在水里的位置是 `(0, −depth(t), fwd(t))`；**`R_Sea`（所有固定在水里的东西的根）放在世界的 `(0, depth(t), −fwd(t))`**。
- **depth(t)、fwd(t)** 是圣经 §6·7a / 7b 的速度表的精确积分（每段 `v = v0 + dv · smoothstep((t − t0)/dur)`），`Act07_Sea/Tools~/act07_motion.py` 和驱动里的同一套公式；F2h 时车的原点在水下 1.0 m（水正好到窗台），眼睛在 **363.615** 没进水里。峰值加速度 0.28 m/s²（圣经 ≤ 0.28）。
- **标签**：`FromLocal/cues.json` 有的用它的；v2.1 的子标签（F3e、F3e1–3、F3i、F4p、F5p…）还没进 `cues.json`，用圣经 §2.1 的秒数（`Engineering/cues_v21_patch.json` 等本地合并）。JSON 的 `labels` 块写着每个标签取自哪里。
- **眼位**：主座位 (0.55, 1.70, 2.05) = Gate `cameras.U7` = 标准台 `hero`；`LB_Journey.heroEye` 是 (0.70, 1.77, 0.20)，两者不同，**参考帧按前者**。

网格全部由搭建脚本按 JSON 生成（`Act07_Sea/Meshes/*.asset`）：粒子要 4 分量的 UV（FBX 只能带 2 分量），bounds 按 shader 实际画到的地方给（粒子和光柱在顶点着色器里移动）。

**驱动 `LanbaiAct07Driver`**（CONTROL §5 的三个方法）：
- `LanbaiWindow()` = {F2h − 1, 出海 + 1} = {362.26, 923.36}（整个第 7 幕；本包只做 7a，F5 以后保持 7a 的画面终态，7b / 7c 以后接在同一个驱动里。注意：F5 以后驱动照样按 7b / 7c 的速度表积分深度和前进，`R_Sea` 跟着走，7a 的东西会慢慢离开视野——这是 7b / 7c 包来了以后的事）。
- **两道门禁**：t < **tEntry**（F2h 363.26）什么都不写、海的东西全关（云的海还在）；t ≥ **tExit**（出海 922.36）只交还海独有的量（`_Udon_Underwater` = 0、`_Udon_Caustics.x` = 0、主光上的 cookie 摘掉），关掉平面、穹顶、聚光、粒子，**任何共享通道都不再写**（雾、RenderSettings、Trilight、SeaMode、SeaLevel、`_Udon_T`、主光的方向 / 颜色 / 强度）。
- `LanbaiActivate(on)`：开关 `R_Sea`、`R_Act07Bus`；关的时候同上只交还海独有的量（裁决 20:40 补充）。**主光从不关**。
- **预热**：`Start()` 只初始化，不关任何 renderer；海面在搭建时挂的是 **BELOW** 材质（`_below` 初值 true），所以分发层出生时的 2 帧预热把 363.615 才第一次用到的 `_SEA_BELOW` 变体也画了一遍；第一次 Tick 才按门禁关、并换回 ABOVE（不在 363.26 那片静里卡一帧）。主光挂 cookie 的变体见 §8 第 8 条。
- **拖时间轴往回**（调试时钟）：回到眼睛进水之前，驱动把主光上的 cookie 摘掉，主光交还第 6 幕的写的人。
- `LanbaiTick(t)` 每帧：`R_Sea` 的位置；平面的材质（ABOVE → BELOW）和 `_WindowGain` / `_WindowCore`（MPB）；全局量 `_Udon_T`、`SeaLevel`、`SeaMode`、`SeaClock`、`Underwater`、`SeaBus`、`SeaBusVel`、`Fog`（+ `FogBase` = (海面 y, 0, 0, 1)，水下不起作用但 w > 0）、`WaterFogUp/Mid/Down`、`Caustics`（+ `Color`、`Tex`）；**接管**（`Engineering/README_集成.md` §2–3，两个开关**默认关**）：`writeRenderSettings` → `RenderSettings.fogDensity / fogColor / ambientMode = Trilight / ambient*`；`writeMainLight` → 世界主光的方向、颜色、强度和焦散 cookie；光柱、最后一道光柱、落在座椅 / 手上的聚光（`Act07_Beam`）、粒子、石壁、暖点、穹顶的开关和 `_Gain`。灯和 RenderSettings 的颜色都填 sRGB（Unity 自己线性化）、强度直接填线性照度 E（D-00：VRChat 强制 `lightsUseLinearIntensity = true`，圣经 §1.5 陷阱 1 已作废）。
- **不写**：PPv2（`LB_Journey`）、车厢（`_Udon_Cabin*`，车厢驱动）、F2h 之前云的海。
- `writeRenderSettings` / `writeMainLight`（默认都关）：本地勾了 `extAtmosphere` / `extSun` 才勾，否则和 `LB_Journey` 抢写。

## 4. 车顶的侵蚀和 VR 的窗

圣经 §4.8：车厢侵蚀 F2h → F5 从 0 到 0.25，从天窗的边开始，≈387 s 从破洞里看得见斯涅尔之窗。侵蚀的 shader 是车厢的（总导演的 `Cabin/`），所以：
- 参考帧用标准台车壳加一个“车顶的洞”近似：仰角 ≥ `70 − 120 × 侵蚀(t)` 的方向全开（387 s：约 67°）；`roofhole=40` 是最坏情况（整个车顶都没了）。
