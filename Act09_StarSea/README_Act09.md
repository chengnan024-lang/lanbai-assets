## 3. 银河点燃线 g(t)

- **按光源点燃，不碰曝光**（圣经 E18）：星点在 F13 一帧全部出现（+0.00 EV），亮度的上升全部来自辉光与星空底。
- **一口气，不是“跳一下、停一下”**（终审 #1）：v1.2 的表在 F13 后 0.05 秒就把 g 从 0 推到 0.08（银心码值 6 → 52），再停 0.45 秒。现在：
  - **0 → 0.7 秒**：g 从 0 平滑地（三次曲线，起点斜率 0、终点斜率接上后段）涨到 0.078，即正前方的平均亮度刚到爬升律地板 0.004 的那个 g；
  - **0.7 → 4.2 秒**：正前方的 L 按 EV 线性从地板涨到满（3.0 EV / 3.5 秒），1022.41 满。
- **银心先亮 0.3 秒**（终审 #1 的“鼓励做”）：`_Udon_GalaxyGain` = (旋臂 g, 银心 g_core, 1, 1)，shader 按银经插值（`LanbaiGalaxyGainAt`，`Common/Shaders/LanbaiSky.cginc`：离银心 15° 以内全用银心的，60° 以外全用旋臂的，45° 软边，与银纬无关，所以光沿着带走）。g_core 是同一口气提前 0.3 秒：地板以下的起步短 0.3 秒（0.4 秒），之后的 EV 线性段整体提前，**涨的速度和旋臂一样**，所以哪个视向都不会比旋臂涨得快。
  - 试过的：0.5 秒、银心按时间压缩着涨（更快）→ 正前方 2 秒窗 1.95 EV，超了 1.8；0.5 秒的平移会让银心自己的起步只剩 0.2 秒（又是一跳），所以上限定 0.3 秒，按 0.3 / 0.2 / 0.1 / 0 从大到小试，0.3 就过了。
- **爬升律按真正渲染出来的帧量**（每个像素自己的增益，含星，每 0.05 秒一帧），五个视向全过、全单调：

| 视向 | 0.25 s（≤ 0.5） | 1 s（≤ 1.0） | 2 s（≤ 1.8） |
|---|---|---|---|
| 正前方 | 0.23 | 0.86 | 1.71 |
| 抬头 60° | 0.20 | 0.76 | 1.42 |
| 天顶 85° | 0.19 | 0.72 | 1.34 |
| 银心（−30°, +12°） | 0.21 | 0.82 | 1.61 |
| 向下 60° | 0.19 | 0.75 | 1.42 |

- 点燃满时只有天的 APL：正前方 35.5、抬头 27、银心 31。两张表在 `Act09_StarSea.json` 的 `ignition.g` / `ignition.g_core`（每 0.05 秒一个），各视向的 L(t) 在 `Data/ignition.json`。
- **在 Unity 里重新标定**（带车厢）：F13 那一帧的正前方截图平均亮度 C、g = 1 时 G（再加 g = 0.25 / 0.5 / 0.75 三张求 L(g)），按上面的两段重算表（`act09_calib.py` 的 `ease_table`）。带车厢时跨度会小（车厢暗）。

## 4. 驱动写什么（`LanbaiAct09Driver`，单独的常开物体 `Lanbai_Act09Driver`）

| 全局量 | 值 | 从 |
|---|---|---|

| `_Udon_SkyFx` | (0, 0.85, 0, 1)：蓝时的带留着，被夜层盖住 | 1001.21 |
| `_Udon_Fog` | (0, 0, 0, 1)：雾关 | 1001.21 |

| `_Udon_ZenithColor`、`_Udon_HorizonColor`、`_Udon_FogBandColor`、`_Udon_NadirColor` | (夜色 + g × 星空底增量, 1)，四个同值（**镜子读 ZenithColor 当星空底**；和 `star_sea` 预设一样，`LanbaiHorizon` 也落在星空底上，不会在蓝时的地平线和近黑的红天顶之间插出品红） | 1009.21 |

夜色和星空底增量从 `Sky/SkyPresets.json` 的 `blue_hour` 读（`_Udon_Sky_NightColor`、`_Udon_Sky_StarFloorAdd`），和天空一致。
**每帧开销**：`LanbaiTick` 5 个 SetGlobalVector（1009.21 起 9 个）、1 个 MaterialPropertyBlock（第一批星）、两个 renderer 开关，没有循环、不分配内存。
第一批星用自己的材质（`_UseGlobalGain` = 0）和 MaterialPropertyBlock（`_Gain`、`_OrderFade`），不碰全局量。两个星的 renderer **搭建时关着**，由 Tick 打开：第一批星 994.06 → 1010.01，天问的星 F13 起（时间轴往回拖时也会关回去）。主星是 Sky 的 `Lanbai_Stars_BSC5`，本驱动不碰它（增益 0 = 顶点 shader 里剔掉）。
**交接**（两个边界）：
- **1001.21** 之前 `_Udon_SkyBlend / SkyFx / Fog / GalaxyGain / StarGain` 归第 8b 幕（「云」）的驱动，之后归本驱动；**8b 的驱动在 t ≥ 1001.21 时不再调用 `LanbaiSkyPreset` 的 Apply / ApplyBlend**（Apply 一次写全部 68 个名字，会成第二个写的人，D-22）。`blue_hour` 预设里这几个量和本驱动在 1001.21 写的一样，所以接得上。
- **1009.21** 起本驱动再写 `_Udon_ZenithColor / HorizonColor / FogBandColor / NadirColor`。
- **1149.31**（F16）起 `Lanbai_SkyDriver_Acts11to12` 应用 `overcast_rain_night`，写全部名字。
**窗口的例外**：`LanbaiWindow()` 从 992.06 开（蓝时里，看得见的时候），不是在遮挡下（Director README §3.2）。激活那一帧什么都看不见：两个 renderer 关着，第一批星的增益是 0（994.06 起才有），天问的星 F13 才开，全局量在 1001.21 之前不写。窗口的结束（F16，白）在遮挡下。

## 5. 星的亮度

- 主星：`_StarScale` 1.6、`_MagRef` 0、`_MagSlope` 0.5（物理是 1；压缩到 0.5，6.5 等的星也读得出）、FWHM 1.6 px、最亮 50 颗 ×4。0 等星的峰值线性 6.4（会 bloom），6.5 等 0.08。
- **天问的 16 颗星**（终审 #4）：每颗仍在“它那个字原来的位置”（`Fonts/strings_all.json` 的 P09_Tianwen 排版：方位 0°、仰角 +8°、50 m、字高 2.2°），但落在**这个字笔画最密的交点**（思源宋体的墨迹按 0.06 em 模糊后的最大值），不是字框中心：相对字框中心横向 −0.32 … +0.30 em、基线以上 0.34 … 0.64 em，两行不再对齐成格子。HDR 峰值按笔画数 1.2 × 5^((笔画 − 3) / 9) = **1.2 … 6**（×6，按圣经；1.75 等的范围）：遂、道（12 画）6.0，谁（10 画）4.2，其余 1.2 … 2.5，两三颗领头，读成一个星座。颜色 `#F2F6FF`（材质 `_Tint`，亮度归一）。
- 第一批星：真星的星等 × 0.55，色 `#E8EEF8`。

## 7. 诚实的已知弱点

- 满亮时正前方左侧的银心（暖尘）是画面里最亮的一块，只有天时正前方 APL 36（圣经 30 是带车厢的整帧）；要压的话在 `Act09_StarSea.json` 里把 g 的上限乘 0.85，等带车厢的截图再定。
- 1008.6 那一帧：最后的光是贴着地平线、约 3° 高的一条线，顶边平；它的下沿（地平线以下按 4 倍仰角算）很利，约半度。地平线以下是和天一样的黑，没有东西接住它；有车厢 / 地面时再看。
- 紫带（D-21：h 290–330、C\* > 8、L\* > 40）：只有天时 1022.41 / 1100 / 1137 都是 0；加上星以后 1137 还有约 0.0015%（正前方）/ 0.0008%（银心视向），约 8 个像素，是蓝白的星的边缘叠在暖色辉光上。v1.2 是 0.13–0.48%。把旋臂整体往蓝推试过，不改变这几个像素，没做。
- 星的星等压缩（0.5）和亮度是按“看得见、F13 那一帧仍在地板以下”定的，满天星的密度感要等头显里看。
- 参考帧没有镜子、没有车厢、没有字；APL 是“只有天”的数，不能直接和圣经 §2.2 的整帧 APL 比。
- 第一批星的出现时刻（994.06 → 997.06）是我定的（圣经只说“在天顶出现”）。
