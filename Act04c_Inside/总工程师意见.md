   ```csharp
   public float[] LanbaiGrade(float t)   // {ΔEV, WHITE_SAT, WHITE_BLOOM, 桌面镜头层乘数}；没有事件 return null

   public float[] LanbaiGrade(float t) { float d = LanbaiDeltaEV(t); return d != 0f ? new float[] { d, 0f, 0f, 1f } : null; }
   ```
   `LanbaiDeltaEV` 保留给遮罩补偿内部用。README / DESIGN 第 79 行的“由分发层合成后写一次”改成指向 `LanbaiGrade`。等你的包合进 main，我在差异表里请本地删掉 `ApplyGrades` 里自己的 `FLASH_TEAR`。

## 二、建议

- **透明叠绘没有数**：DESIGN 第 90 行写了“每像素层数在袖里最多（2 圈毛边 + 壁纱 + 车厢玻璃）”，美术评审 r05 又提到“181 层太多”。请用标准台量（main 上 `Engineering/render_harness/README.md` §5.5：场景脚本里给每个透明物体设 `ob['lb_fse'] = '<层名>'`，`lbh_render.py ... --fse`），在 181.0、LIP4、袖中段（≈ 215）、袖出口（231）四个时刻出 `fse.json`，放进 `Docs~/`。上限：持续 ≤ 4 FSE（含车厢玻璃 0.7）、峰值 ≤ 7、任一像素 ≤ 8 层。门内的雾很浓，看不见的层也照样画——如果袖里超了，最省的办法是把雾 ≥ 90% 以外的层整层关 renderer（你已经在用“雾 < 90% 才算看得见”这个定义，同一个阈值）。
- **`LanbaiOverlay.EvOverlayAlpha` 是跨类调用的 static 方法**（驱动第 330 行）。UdonSharp 1.x 对“别的 U# 类的 static 方法”支持与否要本地编一次确认；保险起见在驱动里复制一份（十几行），或者改成实例方法 `overlay.EvOverlayAlpha(...)`。README 的“没在 Unity 里编译过”那一节加一句。
- **遮罩的填色补偿用的是你自己的 ΔEV**（`overlay.SetFlat(blackFillS4c, a, LanbaiDeltaEV(t))`）。第 5 幕那 0.25 秒里只有 `FLASH_TEAR` 一个曝光事件，所以“你自己的 = 这一帧的全部”成立；README 里写明这个前提（以后别的包在 248.39 → 248.64 加曝光事件时，补偿要改成读分发层的 `gradeDEV`）。
