## 1. 阻断项

### B1 · 变形的前一半，日线是两条（D-39 #2 没做到）

`SunNow()` 让太阳在 956.36 → 964.36 用 smoothstep 从 +0.5° 沉到 0°。同一段里，`_Udon_SunDisc.z` 让日线从 0 长到 ±10°，`ApplyBlend` 让另一片天（`_Udon_SkyFx.x`）从 0 淡入到 1，三条曲线是同一条 smoothstep。两个日盘要等仰角 ≤ 盘的半径（0.265°，算上峰值锐化后的可见核心还要更小）才贴上，这时 w 已经过了 0.6，大约在 961.5 以后。在那之前，线已经长到 ±3…6°，另一片天的权重也已经有 0.3…0.6，所以地平线上下是**两条平行的线，中间夹着一条背景色的缝**。

CPU 天空实测（方位 0° 那一列，亮度按同一个比例归一）：

| t | 太阳仰角 | 线半长 | 上线 | 下线 | 两线之间最暗处 | 背景 |
|---|---|---|---|---|---|---|
| 959.2 | 0.36° | 2.9° | 0.75 @ +0.36° | 0.47 @ −0.39° | 0.39 | 0.41 |
| 960.0 | 0.28° | 4.3° | 0.75 @ +0.29° | 0.50 @ −0.31° | 0.40 | 0.41 |
| 961.0 | 0.19° | 6.2° | 0.75 @ +0.21° | 0.54 @ −0.24° | 0.47 | 0.42 |
| 964.36 | 0° | 10° | 一条（±0.01°） | | | |

959–961 这段，两线之间的缝落回到背景亮度，缝宽 0.1–0.2°，在 VR 里是 2–4 个像素。这正是 D-39 #2 说“像渲染错了”的那种画面，而且落在全幕唯一的变形上，视线这时正跟着翼看向太阳。

`Docs~/iterations/01_sun_line.png` 只验了两个终态（+0.5° 和 0°）。参考帧里 8i → 8ii 的中间键（0.25 / 0.5 / 0.75）没有带日线，也没有带下沉，所以这一段在参考帧里看不出来。

改法（选一种，改完把 956.5 → 964.5 每 0.5 s 一张的日线小块放进 `Docs~/iterations/`）：
- 日线等两个日盘贴上了再长：`line = lineDeg × S((t − tTouch)/(tF10e + 8 − tTouch))`，tTouch 取仰角落到约 0.12° 的时刻；
- 或者让太阳先沉：例如 3 s 内沉到 0°（约 0.17°/s，还是很慢），日线和另一片天仍走 8 s。两个日盘在地平线上贴近、合拢读起来是自然的，两条平行的线读起来不自然。
