## 0. 先说结论

- **旧车厢**是本地 v1 世界的占位车 `Lanbai/Bus/Model`，材质全是本地的 `LB_LitPBR`（玻璃 `LB_GlassPBR`）。它的“慢慢消失”是 `LB_Journey.SetBusAlpha` 往每个 renderer 的属性块写 `_Alpha`，shader 按屏幕像素做棋盘格 dither。1025 s 时 `_Alpha` = 0.45，截图 05 右下那一片棋盘格就是它。
- 它**不是** 1025 s 大面积白闪的根因。那是 VRC 镜面盖掉了旧海面的属性块，本地已经修了，总导演已采纳。但它是一直存在的细闪：强制不透明以后，相邻帧差的中位数从 5.93 降到 3.54（§2）。圣经 §4.8 也写明了“用 clip 不用抖动”，§1.8 不许 VR 里有锁屏的东西。
- **先交版**是菜单 **`蓝白/Build/车厢（先交）/搭建（车厢 + 车外皮）`**（`Bus/Editor/LanbaiBusCabinDropIn.cs`）。它从 `Bus.fbx` 搭整辆 PAZ-672M，挂在旧车的根 `Lanbai/Bus` 下面（原点、不转）。全部表面用 `Lanbai/Cabin`：漂白，加世界坐标 FBM 上的 clip 侵蚀（D-32 #1 后两项取补），带 `LanbaiCabinDriver`。报告里没有 ERROR，搭完才把旧车关掉（不删）；有 ERROR 就只搭好、不换。`LB_Journey` 一个字段都不改。
- 漂白和侵蚀要分发层每帧调 `LanbaiCabinDriver.LanbaiTick(t)`，所以本地要跑一次 `蓝白/Director/1 Generate Dispatcher` 和 `2 Wire Scene`（§5 第 4 步；要有 HANDOFF_LOG 的明文）。不跑也能看车，只是车厢一直是 t = 0 的样子：完整、管灯亮，不会消失。车厢驱动报了 `LanbaiTakesOverNothing()`，它的全片窗口不会让 `LanbaiCovered(t)` 处处为真。

## 2. 为什么它会闪（能证明的、不能证明的）

- 棋盘 dither 的格子钉在屏幕像素上，后面的车厢却跟着头在动。格子不动、内容在动，看起来就一直在爬。VR 里两只眼的格子落在不同的东西上，就是细闪。圣经要避开的正是这个：§1.8 VR 里不许有锁屏元素（`Art/ART_BIBLE.md` 第 256 行），§4.8 “用 clip 不用抖动”（第 606 行）。
- 本地量过一次（`FromLocal/flicker_fix/20261025-0315/`）。条件：1023–1041 s，177 帧，同一台诊断相机，±1.2 cm 微动。量的是相邻帧的平均绝对差，0–255：

| 条件 | 中位数 | 95 分位 | 最大 |
|---|---:|---:|---:|
| 原状（`baseline_props`） | 5.93 | 36.94 | 132.11 |
| 强制旧车不透明（`opaque_props`） | 3.54 | 31.86 | 113.36 |
| 修了海面属性块（`fix_direct`） | 2.98 | 8.01 | 30.45 |

  强制不透明以后，平时的细碎变化少了大约四成，但大跳亮还在（本地 README 第 28 行；`FromLocal/flicker_1025/问题.md` 的 -04）。
- 结论：棋盘消散是一直存在的细闪来源之一，不是大白闪的根因。换车只解决这一件，镜面、白段、星海占位各归各的包。
- 推不出来的：
  - 这些数是编辑器里单眼相机的帧差，不是头显里的感觉，也不是闪烁频率；
  - 新车 clip 侵蚀的边在头显里闪不闪，也要实测（§6）。

|---|---|
| **搭建（车厢 + 车外皮）** | 推荐用这个，见下面 |

### 搭建做的事

1. **守门。**
   - Play 模式里不做。
   - 当前场景是正式场景 `Assets/Lanbai/Scenes/Lanbai.unity` 就拒绝。D-46 #3：进正式场景要本地技术验收和小楠的美术确认。

   - 守门拒绝了，菜单状态（`LanbaiUdonPrograms.MenuStatus`）也记成 FAILED，不会留着上一次的 DONE。
   - 缺 `Lanbai/Cabin`、`Lanbai/ThinCloth`、`Bus.fbx` 或 `BusLayout.json` 时，场景一点都不动。
2. **U# 程序资产**（D-41，`Common/Editor/LanbaiUdonPrograms`）：
   - 要的是 `LanbaiCabinDriver`、`LanbaiBusSeat`，项目里有 `LB_Seat` 的话也算上；
   - 缺的建在 `Assets/Lanbai/Bus/Programs/`（和 `蓝白/Build/车` 同一个地方），等 SDK 初始化完再搭；
   - 已经有的按类型复用。
3. **删掉上一次的 `Lanbai_Bus`。** 只认这个名字。它和 `蓝白/Build/车` 用同一个名字：一个场景只放一辆车。
4. **新建 `Lanbai/Bus/Lanbai_Bus`**（原点、不转），`Bus.fbx` 解包放进去，命名为 `Model_PAZ672`。
   - `busRoot` 不在原点、或者有旋转缩放，就报 ERROR。原因：`Lanbai/Cabin` 的侵蚀、座位球、地板洞都按“车坐标 = 世界坐标”算（`Cabin/Shaders/LanbaiCabinCommon.cginc` 第 18 行）。

   - 其余车厢件用常数照度；
   - 外皮用 uv1 上的外观图集；
   - 窗帘用 `Lanbai/ThinCloth`；
   - 33 块玻璃用 `Lanbai/BusGlass`。没有这个 shader（`Rain/Shaders` 没同步）就报 ERROR、玻璃全关。

   - 再读一遍这些材质用到的贴图的导入类型（只读，不改）：法线图（`_PartNormal`、`_DetailNormal`、`_WeaveNormal`）不是 Normal map，遮罩（`_PartMask`、`_DetailMask`、`_AtlasMask`）或管灯光照图 `_CabinTubeLM` 不是 Default + 线性，都报 ERROR。雨玻璃的三张数据图不对只报警告（`Rain/README_Rain.md` §1）。

   - 外皮建 LODGroup：屏高 > 12 % 用 LOD0，> 0.5 % 用 LOD1。

8. **碰撞体**：`BusLayout.json` 里的 11 个盒子，地板顶面 y = 0.62。
9. **`LanbaiCabinDriver`**：放在单独一个物体上，一直开着。
   - 窗口 `LanbaiWindow()` 是 [−600, 100000]。片尾是 1729.96（`FromLocal/timeline_v1.md` 第 38 行），但 `LB_Journey` 的时钟过了片尾还在走，一直停在“醒”，不自动重开。所以窗口不设结束：迟到的人、跳到片尾以后的，拿到的都是第 12 幕的状态（收音机表盘灭着），不是 `Start()` 的 t = 0。第 12 幕（1251.96）以后，驱动的每条曲线、门、玻璃、窗帘都是常数。

   - 引用：所有 `Lanbai/Cabin` renderer（含外皮，D-26 的洞要穿过车底）、窗帘、33 块玻璃、23 个座位中心、主座位、四片门和关门的位姿；

### 检查（只读）

它会列出这些，什么都不写：

- 输入：四个 shader 在不在；`Bus.fbx` 的导入（不生成第二套 UV、网格不压缩）；贴图的导入类型（`Generated/Materials` 里材质用到的，加上 `Bus/Textures/Parts` 的 `*_Normal_*`、`*_Mask_*` 和 `Cabin_TubeLM.exr`，所以第一次搭建以前也能查）；Vertex Compression（Color、TexCoord0–3 不压缩，D-40b #3）；层；有哪些灯照得到 Bus 层；U# 程序资产的状态。
- 场景：`busRoot` 在不在原点；现在用的是哪辆车；出发按钮在哪、开没开、旧位置有没有记下（用着新车时它在 `cabin_bounds` 外报 ERROR）；水线挂在哪辆车上；`busRoot` 下还留着什么（烘好的反射探针、culling 含 Bus 层的点光会报）。
- 驱动：`LanbaiCabinDriver` 有几个、开没开、引用数、`yieldToInside`、窗口、有没有 `LanbaiTakesOverNothing()`；门内驱动的窗口；分发层有没有指向它；生成的 `LanbaiActDispatcher.cs` 里有没有把它排出 `windowsFlat` 的那一行；在 Play 里点，还读分发层的 `windowsFlat`，里面有全片窗口就报 ERROR。
- 会抢写全局量的东西：场景里有没有切片用的 `LanbaiBusSliceGlobals`，或者开着的 `*TestClock`。
- `LB_Journey` 和收音机：建议改的字段、`RadioAnchor` 和 `LB_Journey.radio` / `radioNoise` 该挪到哪，只列不改。
